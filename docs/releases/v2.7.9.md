# v2.7.9 — Fast Purchase & Reliability

## Summary

This release line simplifies the public purchase journey before adding new features. The intended fast path is now:

```text
Hero → three-step orientation → Menu → Bag → delivery details → review → WhatsApp
```

Exploration features remain available, but they no longer compete with the primary conversion path.

## Customer-facing changes

- Menu moved directly below the purchase-orientation section.
- Hero reduced to one primary purchase CTA plus optional Rosa help.
- Primary navigation reduced to four high-value destinations.
- Desire discovery moved behind progressive disclosure.
- Product cards reduced to Add + Personalize; favorite/share moved to product details.
- Bag now has one dominant continuation action.
- Checkout removes redundant visible city/state fields while keeping the configured Serra — ES boundary explicit.

## Reliability fixes

- Partial/changed CEP input clears stale address fields and invalidates older lookups.
- Review cannot continue while an eight-digit CEP lookup is still pending.
- Stored checkout values are sanitized before being written into controls.
- Failed checkout opening returns the customer to the Bag with the order intact.
- Rosa opened from the Bag returns focus to a visible Bag trigger when closed.
- Checkout review focuses the updated dialog heading before the final WhatsApp action.
- Brand synchronization now locates the header logo semantically rather than depending on attribute order.

## Quality evidence

The release adds `tools/conversion-flow-check.py` to protect the fast-path information architecture, CTA hierarchy, checkout recovery, focus contracts and all `2.7.0`–`2.7.9` changelog entries.

Automated checks do not constitute NVDA, JAWS, Narrator, TalkBack, VoiceOver or real-device evidence unless those tools/devices were actually executed.
